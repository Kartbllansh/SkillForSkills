# Отчёт об обновлении SkillForSkills

Дата: 19 октября 2026 года. Основа сравнения: коммит `e1a4309`, one-chat 0.3.0 и archive 0.2.0. Первичное обновление выполнено в локальном репозитории; публикация, merge и развёртывание сервиса в его объём не входили. Последующий пилот и подготовка публикации описаны в дополнении в конце отчёта.

## 1. Что изменено и зачем

Сохранены подробные анализаторы и способ запуска одним Markdown-вложением. Пользователь получает обоснованную рекомендацию либо готовое более простое улучшение. Отрицательный результат больше не должен заканчиваться только словами «нужен шаблон» или вопросом о регулярности уже понятной задачи.

Добавлены две самостоятельные lite-версии с меньшим объёмом задачи и анализа. Во всех версиях согласованы доказательства, актуальное подтверждение перед созданием рабочего скилла, честность охвата, первое применение и короткие сообщения о данных и контакте.

Бизнес-цель — привлечение клиентов на работу с ИИ в компаниях — поддержана проверяемой пользой, возможностью передать метод и прямым добровольным контактом. Принудительного корпоративного предложения, обещаний экономии и целевого числа создаваемых скиллов нет.

Следующие механизмы сохранены или уточнены, а не добавлены впервые:

## 4. Различия full и lite

| Версия | Объём задачи и процесс | Результат и границы |
|---|---|---|
| One-chat full | Подробное восстановление задач, поиск по признакам и проверка пользы | Одна основная рекомендация либо полезная альтернатива; возможна одна обоснованная необязательная заметка |
| One-chat lite | Один доступный диалог или фрагмент, один проход без классификаций и отчётности по каждому признаку | Не более одной возможности; компактная самостоятельная инструкция после согласия |
| Archive full | Обзор доступных текстов частями, объединение между чатами, перепроверка кандидатов, реестр охвата | До пяти рекомендаций, стабильные номера и создание выбранных файлов; продолжение при незавершённом обзоре |
| Archive lite | Небольшая порция целых диалогов или законченных эпизодов; подготовка инструментами, один ограниченный проход | Не более одной рекомендации; вывод только по порции; короткая запись границ вместо реестра всего архива |

Lite не является сокращённым отчётом после полного анализа. Уменьшены сам вход за проход, число кандидатов и объём обязательных процедур. При этом сохранены подтверждение, доказательства, защита от команд из истории, дубли и ветки, полезный отказ и проверка фактического создания файла.

Размеры подсчитываются по полному файлу, включая заголовки и YAML, как число непустых последовательностей между пробельными символами (`\S+`). Это воспроизводимый счётчик слов, **не количество токенов**. Байты — фактический UTF-8 файл в рабочем дереве; размер в Git может отличаться из-за перевода строк.

## 5. Полезный отрицательный сценарий

Ниже синтетические примеры ожидаемой подачи, не результаты запусков:

**Достаточно шаблона.** «Для фиксированных полей отдельный скилл не нужен. Заготовка: „Задача: …; срок: …; ответственный: …; неизвестное: нет данных“. На ближайшем статусе проверьте, все ли нужные поля заполнены без повторного объяснения формы».

**Задача понятна, повторяемость неизвестна.** «По одному отчёту устойчивый метод пока не подтверждён. Предложение для этой задачи: „Для каждого вывода укажи подтверждающий фрагмент; если основания нет, пометь предположение“. На следующем разделе проверьте, легче ли сверить выводы с фактами». Скилл автоматически не создаётся.

**Контекста нет.** Один вопрос: «Какую ближайшую рабочую задачу вы хотите упростить? Достаточно одной фразы». После ответа — сразу улучшение, заготовка и проверка; уже названную задачу не спрашивать повторно.

**Техническое препятствие.** «В этой среде нет чтения ZIP; содержимое не проанализировано. Приложите один уже доступный рабочий диалог текстом». Это запрос материала, а не отрицательный вывод и не завершённый полезный результат для показа контакта. При переходе на другую доступную задачу анализатор должен назвать смену основания.

## 6. Контакт и данные

Точная строка контакта:

«По вопросам и сотрудничеству: [@mark0vartem](https://t.me/mark0vartem).»

В README — видимый короткий раздел. В каждой инструкции — один показ за запуск после первого завершённого полезного результата: рекомендации, готовой альтернативы или сообщения о созданном скилле. После запроса данных и ошибки чтения контакт откладывается. Если уже показан после анализа, после создания и продолжения не повторяется. В созданные рабочие скиллы контакт, рекламная подпись и требование их показывать не включаются.

Точный комментарий:

«Скилл не отправляет переписки авторам проекта. Данные обрабатываются в выбранной вами ИИ-среде.»

В README он расположен перед шагами загрузки в обоих сценариях; это намеренные два размещения в документе. Анализатор показывает его один раз в первом ответе, даже если требуется исходный материал. При создании после анализа строка не повторяется. Она не обещает локальную обработку или правила хранения сервиса.

Две строки считаются отдельно от длины основного ответа. Контакт стоит последним после единственного вопроса или следующего шага. Новых обязательных экранов согласия и второго действия они не вводят. Рабочая/командная заметка допускается только при видимом контексте и как возможность для проверки.

Проверены официальные Markdown-инструкции проекта и описание существующего Telegram-сценария. В анализаторы не добавлены код передачи, телеметрия, автоматическое открытие ссылки и отслеживание. Бот — отдельный существующий канал: он пересылает присланные пользователем публичные ссылки администраторам. README прямо называет это исключение из возможного широкого толкования заявления о данных; сам бот не изменён.

Границы обещаний дополнительно сверены с [официальной документацией OpenAI о локальной обработке и данных](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-local-security): локальное выполнение само по себе не означает обработку моделью только на устройстве; хранение зависит от категории данных и среды. Ссылка на [руководство по постановке задач](https://learn.chatgpt.com/docs/prompting) сохранена в README. Сервер OpenAI Docs вернул HTTP 403; страницы прочитаны через веб-инструмент. Эти источники не доказывают пригодность конкретной среды пользователя.

### Редакторский разбор ожидаемого поведения

Проверены маршруты по текстам инструкций; это **не фактические прогоны скиллов на модели**. Дополнительно выполнено независимое read-only ревью README, четырёх инструкций и плана: Critical/Important замечаний не найдено. Одно Minor-замечание исправлено: первое применение теперь явно требуется и при выдаче текста без сохранённого файла; аналогичное уточнение добавлено в archive full. Синтетические входы и ожидаемые исходы сохранены в плане экспериментов.

| Сценарий | Ожидаемый переход, который проверен редакционно |
|---|---|
| 1. Один метод в независимых задачах | Обоснованная рекомендация с видимым эпизодом; создание после согласия. Full archive может показать до пяти разных методов, lite — один |
| 2. Много исправлений одного результата | Одна задача, не множество выполнений; без основания для будущего применения — заготовка по текущей работе |
| 3. Один пример и план серии | Предложение допустимо; серия прямо называется планом пользователя, не наблюдаемой частотой |
| 4. Достаточно настройки/шаблона | Готовая небольшая заготовка в ответе и одна проверка, без отдельного скилла |

| 6. Материала нет | Один вопрос о ближайшей задаче; после ответа — готовый материал, без интервью и «Хотите продолжить?» |
| 7. Архив недоступен или превышает ресурсы | Конкретное ограничение и минимальный доступный вход; нет отрицательного вывода о работе или требования делить архив вручную на десятки частей |

При наличии средств сохранения ссылка разрешена только после проверки наличия и читаемости. Первое применение содержит задачу, данные и один признак пользы с сохранением качества.
